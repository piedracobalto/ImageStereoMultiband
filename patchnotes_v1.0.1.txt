v1.0.1 — Splitter Frequency Fix + Global Bypass
================================================

Splitter Frequency Fix
----------------------
Bug: When dragging the first crossover splitter in the GUI, the frequency jumped to 20000 Hz
instead of staying at the selected position.

Root cause: In JUCE 8, ParameterAdapter::parameterValueChanged() converts the value to
native (denormalise) before invoking Listener::parameterChanged(). The callback received
the value in Hz but the code called convertFrom0to1() on the already-native value,
treating 116.8 Hz as normalized 0-1 → clamp to 1.0 → convertFrom0to1(1.0) = 20000 Hz.

Modified files:
- Source/GUI/Components/SpectrumCrossoverControls.cpp

  a) parameterChanged(): stores newValue directly in frequencies[] without convertFrom0to1().
  b) setCrossoverFrequency(): writes directly to the raw parameter pointer via getRawParameterValue()
     (which in JUCE 8 returns the denormalized/native value), removing the use of
     beginChangeGesture()/setValueNotifyingHost()/endChangeGesture() and convertTo0to1().

Testing: Dragging any splitter in the GUI should keep the exact frequency selected without jumps.

Global Bypass
-------------
New: Global bypass button at the top-right corner of the header bar.

- When bypass is enabled, the audio buffer passes through clean with no processing.
- A semi-transparent black overlay covers the entire UI (except the header) with centered
  "BYPASSED" text, and all controls are disabled (no clicks received).
- When bypass is disabled, the splitter IIR filters are reset to prevent artifacts/pops
  from stale DSP state (resetDSP).
- The spectrum analyzer and vectorscope are not executed when the plugin is bypassed,
  saving CPU and preventing frozen displays.
